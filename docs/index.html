Every heartbeat labelled, on patients the model has never seen

A small neural network reads the ECG beat by beat and marks each one as normal (N), supraventricular ectopic (S), ventricular ectopic (V) or fusion (F). It runs in this page. The five patients below were kept out of training entirely, so what you see is how it behaves on a new person, not on a heartbeat it has already met.

Why this is not 99%

Most published heartbeat classifiers on this database report 98–99% accuracy. They shuffle all beats together and split them at random, so the test set is full of beats from patients the model trained on, often the beat right next to one in the training set.

The same model, trained the same way, gives both numbers below. Only the split changes.

Where it fails, and why

Ventricular beats transfer well: on new patients the model finds 93% of them, against 77.7% for the classic de Chazal et al. (2004) system on the same split. Supraventricular beats do not.

One patient explains most of it. Three quarters of the S beats in the test patients (1,381 of 1,836) come from record 232, where most beats are atrial premature beats. The model compares each beat with the patient’s own recent beats, which assumes that a patient’s typical beat is normal. In record 232 the typical beat is the abnormal one, so it finds only 4% of them. On the other test patients it finds 53%.

This was found after the one look at the test patients, so the model was not changed to fit record 232: tuning on the test set is the mistake this project measures. Record 232 is included in the strips above so you can see it happen.

Fusion beats are close to hopeless across patients: 372 of the 414 F beats in the training patients come from a single record, so the model has barely seen a second person’s fusion beat.

How it works

Each beat is cut from 0.25 s before to 0.46 s after its R peak (256 samples at 360 Hz). The network sees two versions of it: the beat itself, and the beat minus the median of the patient’s previous 20 beats, which shows how it differs from that patient’s usual shape. It also gets six RR-interval features comparing the time to the previous and next beat with the patient’s recent and longer-term average. A 1-D CNN with about 50,000 parameters, three copies trained with different seeds and averaged, makes the call. All design choices were made by 4-fold cross-validation over the training patients only.

In this page the beats’ R-peak positions come from the database annotations and the 0.5–40 Hz band-pass filter was applied in advance; the two-channel input, the RR features and the network itself are computed in your browser with ONNX Runtime Web.
